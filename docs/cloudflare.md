# تنوع نقطه ورود با کلادفلر

هدف این راهنما یک چیز است: **اگر یک IP فیلتر شد، سرویس کاربر قطع نشود.**

روی Railway فقط یک بک‌اند داری و آن هم در یک ریجن است. ولی می‌توانی چند **نقطه ورود** مختلف جلوی همان یک بک‌اند بگذاری. برای فیلترینگ ایران این مهم‌تر از داشتن چند سرور در چند کشور است، چون مسدودسازی معمولاً روی IP اتفاق می‌افتد نه روی مقصد نهایی.

هزینه اضافه: صفر. پلن رایگان کلادفلر کافی است.

---

## پیش‌نیاز

- یک دامنه (هر دامنه‌ای؛ ارزان‌ترین `.ir` یا `.xyz` هم کار می‌کند)
- سرویس Peyk که روی Railway بالا آمده و دامنه‌ی `*.up.railway.app` دارد

---

## گام ۱ — دامنه را به کلادفلر بیاور

1. در [dash.cloudflare.com](https://dash.cloudflare.com) → **Add a site** → دامنه‌ات را وارد کن → پلن **Free**.
2. کلادفلر دو نِیم‌سرور می‌دهد. در پنل ثبت‌کننده دامنه‌ات، نیم‌سرورها را با آن‌ها جایگزین کن.
3. تا فعال شدن صبر کن (معمولاً چند دقیقه تا چند ساعت).

## گام ۲ — رکورد DNS

در **DNS → Records** یک رکورد بساز:

| فیلد | مقدار |
|---|---|
| Type | `CNAME` |
| Name | `panel` (یا هرچه دوست داری) |
| Target | `<your-app>.up.railway.app` |
| Proxy status | **Proxied** (ابر نارنجی) — حتماً |

ابر نارنجی یعنی ترافیک از شبکه کلادفلر عبور می‌کند. اگر خاکستری باشد کل این راهنما بی‌اثر است.

نتیجه: `https://panel.yourdomain.com` باید پنل را نشان بدهد.

## گام ۳ — تنظیمات SSL

در **SSL/TLS → Overview** حالت را روی **Full (strict)** بگذار.

Railway گواهی معتبر دارد، پس strict مشکلی ایجاد نمی‌کند و امن‌ترین حالت است. حالت Flexible را انتخاب نکن — ترافیک بین کلادفلر و Railway رمزنگاری‌نشده می‌شود.

در **SSL/TLS → Edge Certificates** مطمئن شو **Always Use HTTPS** روشن است.

## گام ۴ — WebSocket

در **Network**، گزینه **WebSockets** باید روشن باشد. روی پلن رایگان پیش‌فرض روشن است، ولی چک کردنش یک ثانیه است — کل پروتکل ما روی WebSocket سوار است.

## گام ۵ — دامنه را به پنل بگو

در پنل: **تنظیمات → دامنه عمومی** را روی `panel.yourdomain.com` بگذار و ذخیره کن.

از این به بعد لینک‌های اشتراک با این دامنه ساخته می‌شوند، نه با دامنه Railway.

## گام ۶ — ⚠️ مهم‌ترین تنظیم امنیتی

حالا **دو** پروکسی جلوی برنامه هست: اول کلادفلر، بعد روتر Railway. هدر `X-Forwarded-For` را هر کدام یک بار به انتها اضافه می‌کنند.

در Railway → Variables:

```
PEYK_PROXY_HOPS=2
```

**اگر این را نگذاری، قفل ورود قابل دور زدن می‌شود** — برنامه IP اشتباه را به‌عنوان IP کاربر می‌خواند و هر کسی می‌تواند IP خودش را جعل کند یا IP دیگری را قفل کند.

بعد از ست کردن، سرویس ری‌دیپلوی می‌شود. در **امنیت → تاریخچه ورود** چک کن که IPهای ثبت‌شده منطقی باشند (نه IPهای داخلی کلادفلر).

---

## گام ۷ — Clean IP: جایی که تنوع واقعی به دست می‌آید

تا اینجا یک نقطه ورود داری: `panel.yourdomain.com`. کاربر آن را resolve می‌کند و به نزدیک‌ترین IP کلادفلر می‌رسد — که ممکن است فیلتر شده باشد.

**Clean IP** یعنی یک IP مشخص از رنج کلادفلر که از ایران خوب جواب می‌دهد. کلاینت مستقیماً به آن IP وصل می‌شود و در هدر `Host` و در SNI دامنه‌ی تو را می‌فرستد. کلادفلر بر اساس همان مسیریابی می‌کند و به Railway می‌رساند.

رنج رسمی IPهای کلادفلر: <https://www.cloudflare.com/ips-v4>

پیدا کردن IP خوب کار آزمون‌وخطاست و از ISP به ISP فرق می‌کند — همراه اول، ایرانسل و مخابرات نتایج متفاوتی می‌دهند. ابزارهای اسکنر جامعه‌ای برای این کار هست؛ من هیچ باینری خاصی را تأیید نمی‌کنم، خودت بررسی کن از کجا می‌گیری.

### افزودن به پنل

در پنل: **لوکیشن‌ها → لوکیشن جدید**

| فیلد | مقدار | چرا |
|---|---|---|
| نام نمایشی | `Clean IP 1` | در کلاینت کاربر همین نمایش داده می‌شود |
| آدرس | `104.16.x.x` | همان IP، خام |
| پورت | `443` | یا یکی از پورت‌های جایگزین پایین |
| Host | `panel.yourdomain.com` | **الزامی** وقتی آدرس یک IP است |
| SNI | خالی بگذار | خودکار از Host پر می‌شود |

فیلد **Host** حیاتی است: وقتی کلاینت به یک IP خام وصل می‌شود، کلادفلر هیچ راهی ندارد بفهمد کدام سایت را می‌خواهی مگر از روی این هدر.

بعد دکمه **تست** را بزن. اگر سبز شد و تأخیر منطقی داد، آن IP کار می‌کند.

### پورت‌های جایگزین

اگر ۴۴۳ روی یک IP مسدود بود، کلادفلر این پورت‌ها را هم برای HTTPS پروکسی می‌کند:

```
443 · 2053 · 2083 · 2087 · 2096 · 8443
```

همان IP با پورت متفاوت = یک نقطه ورود دیگر. رایگان و بدون کار اضافه.

## نتیجه

چند رکورد در «لوکیشن‌ها» بساز: دامنه اصلی، دو سه Clean IP، و چند پورت جایگزین. لینک اشتراک هر کاربر **همه‌ی این‌ها** را شامل می‌شود.

اگر کاربر Clash یا sing-box داشته باشد، گروه `Auto` خودکار کم‌تأخیرترین مسیرِ زنده را انتخاب می‌کند و وقتی یکی فیلتر شود بی‌سروصدا سراغ بعدی می‌رود. کاربر متوجه چیزی نمی‌شود.

برای v2rayNG کاربر باید دستی سرور را عوض کند — ولی حداقل گزینه‌ها را دارد و لازم نیست منتظر تو بماند.

---

## چیزی که این راهنما حل نمی‌کند

**تأخیر.** بک‌اند همچنان یک سرویس در یک ریجن Railway است. کلادفلر نقطه ورود را نزدیک می‌کند، ولی مسیر از کلادفلر تا Railway ثابت می‌ماند.

برای بهبود واقعی تأخیر، به بک‌اند در چند منطقه نیاز است — که یعنی معماری panel + node، چون هر سرویس Railway دیتابیس جدا دارد. آن یک پروژه‌ی جداست.

اگر تأخیر برایت مهم است، ریجن سرویس Railway را روی **`europe-west4` (آمستردام)** بگذار؛ برای کاربر ایرانی از هر سه ریجن دیگر بهتر است.

## عیب‌یابی

| نشانه | علت محتمل |
|---|---|
| پنل باز می‌شود ولی کانفیگ وصل نمی‌شود | WebSocket در Network خاموش است |
| Error 522 یا 521 | Railway پایین است یا SSL روی Flexible مانده |
| تست لوکیشن قرمز است ولی دامنه اصلی کار می‌کند | آن Clean IP از این شبکه مسدود است؛ IP دیگری امتحان کن |
| در تاریخچه ورود IPهای عجیب می‌بینی | `PEYK_PROXY_HOPS` ست نشده یا اشتباه است |
| کانفیگ‌ها هنوز دامنه Railway را دارند | «دامنه عمومی» در تنظیمات پنل ست نشده |
